# Челленджи и вызовы друзьям — дизайн

**Дата:** 2026-07-02
**Статус:** на ревью у пользователя
**Зависит от:** PWA-трекера (localStorage + синк), Node-сервера в `server/` (JSON-хранилище, `/trackerapi/`).

## Цель

Превратить единственный вшитый 75-дневный челлендж в полноценную систему: каталог популярных и трендовых челленджей, несколько активных челленджей одновременно, чекины по дням — и возможность **бросить вызов другу** и следить за совместным прогрессом. Друг может участвовать даже без установленного трекера.

## Ключевые решения

- **Друзья — через инвайт-коды, без аккаунтов** (вариант «комнаты»). Код комнаты — капабилити: знаешь код — видишь комнату. Никаких логинов и паролей.
- **Челленджи — четвёртая вкладка** в таббаре. На «Сегодня» остаётся hero-карточка главного челленджа + чекины.
- **«Трендовые» — кураторский список**: статический каталог в репо с сезонными подборками (зимой — Winter Arc, летом — Summer Shred). Реальной трендовой аналитики нет и не нужно.
- **Чекин — одна отметка в день** (сделал/не сделал). Правила челленджа (список «что входит») — текст-памятка, автоматики по пунктам в v1 нет (YAGNI).
- **Без эмодзи в UI** — карточки различаются акцентным цветом/градиентом по типу, как существующие карточки счётчиков.

## Этапы

1. **Движок челленджей локально** (модель, каталог, вкладка, чекины, миграция старого челленджа).
2. **Комнаты на сервере** (создать, пригласить, совместный прогресс в приложении).
3. **Лайт-страница для друга без трекера** + полировка (шеринг через `navigator.share`, завершение/архив).

Каждый этап — самостоятельно рабочий результат.

## Этап 1 — движок челленджей

### Модель данных (клиент, `state.challenges`)

```js
state.challenges = [
  {
    id: "c_x7f3k2",            // случайный id
    templateId: "winter-arc",  // null для своего
    name: "Winter Arc",
    durationDays: 90,
    startDate: "2026-07-02",   // день 1
    strict: false,             // true = пропуск дня → челлендж провален (как 75 Hard)
    status: "active",          // active | done | failed | stopped
    checks: { "2026-07-02": true },  // отметки по локальным датам
    rules: ["Тренировка каждый день", "Без сахара", "Чтение 10 стр."], // памятка
    accent: "winter",          // ключ цветовой темы карточки
    shared: null               // либо { api, code, participantId, secret } — этап 2
  }
]
```

Производные значения (не хранятся, считаются в `logic.js`):
- `dayNumber = daysSince(startDate, today) + 1`, прогресс `dayNumber / durationDays`;
- **выполненные дни** = количество `checks[d] === true` в диапазоне;
- **стрик** = подряд отмеченные дни, считая от сегодня/вчера (та же семантика, что `habitStreak`);
- `strict`-провал: есть прошедший день без отметки → статус `failed` (предлагаем «Начать заново», старт с сегодня);
- день `durationDays` отмечен → статус `done`.

### Миграция старого челленджа

`storage.js → migrateState()`: если нет `state.challenges`, создать массив и перенести `settings.challenge` в первый элемент:
- `name: "Челлендж 75"`, `durationDays: 75`, `startDate` из `settings.challenge.startDate`;
- прошедшие дни считаем отмеченными (`checks` заполняются от startDate до вчера) — текущий прогресс «День 12/75» не теряется;
- `settings.challenge` остаётся на месте до конца этапа 1 (не ломать старые бэкапы), UI читает только `state.challenges`. Поля «якорь отсчёта / остаток на якоре» из Настроек удаляются.

### Каталог шаблонов — `src/challenge-catalog.js`

Статический массив (данных мало, отдельный JSON-фетч не нужен):

```js
{ id, name, days, strict, rules: [...], desc, accent,
  trend: [10, 11, 12, 1] }   // месяцы, когда шаблон показывается в «Сейчас в тренде»
```

Стартовый набор: **Winter Arc** (90, тренд окт–янв), **75 Hard** (75, strict), **30 дней планки**, **Месяц без сахара** (30), **10 000 шагов** (30), **Холодный душ** (30), **14 дней без соцсетей**, **Медитация 21 день**. Плюс пункт «Свой челлендж» (имя, длительность, правила, strict — вручную).

Секция «Сейчас в тренде» = шаблоны, у которых текущий месяц входит в `trend`; «Популярные» = все остальные.

### UI

**Вкладка «Челленджи»** (`index.html`: четвёртая кнопка в `#tabbar` + `#screen-challenges`; иконка — флаг/мишень в стиле существующих SVG):
1. **Активные** — карточки: название, кольцо прогресса (переиспользовать стиль hero), «День N из M», стрик, для shared — строка участников. Тап → экран деталей.
2. **Сейчас в тренде** — горизонтальный ряд карточек-шаблонов.
3. **Популярные** — сетка 2 колонки, компактные карточки: имя, длительность, пометка «жёсткий» для strict.
4. **Свой челлендж** — кнопка внизу.

**Старт из шаблона:** лист подтверждения — имя (редактируемое), длительность, старт (сегодня по умолчанию), правила, тумблер strict → «Начать».

**Экран деталей челленджа** (тот же паттерн `renderDetailShell`, что «Тренировка» и «Питание»):
- шапка: кольцо, «День N из M», стрик, выполнено X из N;
- большая кнопка **«Сегодня выполнено»** (повторный тап снимает отметку);
- календарь-сетка всех дней: выполнен / пропущен / сегодня / будущий;
- правила-памятка;
- действия: «Бросить вызов другу» (этап 2), «Остановить» (подтверждение), для strict после провала — «Начать заново».

**«Сегодня»:** hero-карточка показывает первый активный челлендж (фото-фон сохраняется), в ней появляется маленькая кнопка-чекин «Выполнено». Если активных несколько — под hero компактные строки остальных с чекином. Тап по карточке → детали (челленджи-вкладка).

**Статистика:** карточка «Челленджи» — завершено всего, лучший стрик. (Минимум; развёрнутая история — вне рамок.)

### Тесты (этап 1, `test/logic.test.js`)

`challengeDayNumber` по startDate, подсчёт выполненных, стрик, strict-провал (пропущенный вчерашний день), `done` на последний день, миграция старого `settings.challenge` (прогресс совпадает с текущим «День N/75»).

## Этап 2 — комнаты и вызов другу

### Модель на сервере (внутри существующего JSON-хранилища)

```js
data.rooms = {
  "WNTR7F3K": {                       // код комнаты, A–Z0–9 без похожих символов, 8 знаков
    name: "Winter Arc",
    durationDays: 90,
    startDate: "2026-07-02",
    strict: false,
    rules: [...],
    createdAt: 1751500000000,
    participants: {
      "p_ab12": { name: "Артём", secret: "<64 hex>", checks: {...}, status: "active", joinedAt: ... },
      "p_cd34": { name: "Дима",  secret: "<64 hex>", checks: {...}, status: "active", joinedAt: ... }
    }
  }
}
```

Лимиты: ≤ 20 комнат, ≤ 10 участников на комнату, имя ≤ 30 символов, комнаты старше `startDate + durationDays + 60 дней` вычищаются при записи.

### API (префикс `/trackerapi`, как существующие маршруты — в Node без префикса)

| Метод | Путь | Авторизация | Назначение |
|---|---|---|---|
| POST | `/rooms` | Bearer (главный токен) | создать комнату из челленджа → `{ code, participantId, secret }` (создатель сразу участник) |
| GET | `/rooms/:code` | код в URL | состояние комнаты **без секретов**: имена, checks, статусы |
| POST | `/rooms/:code/join` | код в URL | `{ name }` → `{ participantId, secret }`; 409 если имя занято или комната полна |
| POST | `/rooms/:code/checkin` | `participantId + secret` в теле | `{ date, done }` → обновлённая комната; дата не в будущем и не раньше startDate |
| POST | `/rooms/:code/leave` | `participantId + secret` | пометить участника `stopped` |

- Создание — только по главному токену: случайные люди не плодят комнаты, а друг получает уже готовый код.
- Ошибки: 404 неизвестный код, 401 неверный секрет, 400 кривые данные, 409 конфликт. Существующий `rateLimit.js` распространяется на все маршруты комнат (коды не переберёшь).
- CORS: текущий `ALLOW_ORIGIN` (Pages) покрывает и приложение, и лайт-страницу — они на одном origin.

### Клиент

- В деталях челленджа «Бросить вызов другу» → `POST /rooms` → в `challenge.shared` сохраняются `{ api, code, participantId, secret }` → лист с ссылкой-приглашением: `https://sedrcoin.github.io/tracker/challenge.html#WNTR7F3K` — «Поделиться» (`navigator.share`, фолбэк — копировать).
- Чекин shared-челленджа пишет и в локальный `checks`, и `POST /checkin`. Офлайн/ошибка сети → чекин копится в очереди `shared.pendingChecks` и досылается при следующем открытии/чекине (локальные данные — источник правды для «своих» отметок, комната — только зеркало).
- Детали shared-челленджа: блок «Участники» — по строке на человека: имя, день, выполнено, стрик, отметка «сегодня уже отметился». Обновляется `GET /rooms/:code` при открытии экрана.
- Присоединение из приложения: на вкладке «Челленджи» пункт «У меня есть код» → `GET` + `join` → у обоих появляется общий челлендж.

### Тесты (этап 2, `server/test`)

Создание комнаты (401 без токена), join (+409 на дубль имени и переполнение), checkin с верным/неверным секретом, GET не отдаёт секреты, валидация дат, leave, очистка старых комнат.

## Этап 3 — лайт-страница и полировка

- **`challenge.html`** (тот же репо/Pages, отдельная лёгкая страница ~без зависимостей от app.js): открыл ссылку с кодом → видит название, правила, участников; «Присоединиться» → имя → `participantId/secret` в localStorage этого браузера; дальше страница = кнопка «Сегодня выполнено» + таблица участников. iOS-подсказка «Добавь на экран Домой».
- Завершение комнаты: после последнего дня — итоговый экран «кто дошёл» (по данным `GET /rooms/:code`).
- В `sw.js` добавить `challenge.html` в кэш-список с той же версионной схемой `?v=`.

## Безопасность и приватность

- Код комнаты — единственный «пароль» на чтение: в комнате видны только имя и отметки, никаких данных трекера. Ссылку шлёшь только друзьям.
- Секрет участника — 64 hex, сравнение через существующий `tokenMatches` (постоянное время).
- Главный токен трекера в комнатных запросах друга не участвует нигде.
- Личное состояние трекера (`/state`) не меняется и остаётся под главным токеном.

## Вне рамок

- Аккаунты, push-уведомления, лидерборды за пределами комнаты, автоматический чекин по данным трекера (шаги/тренировки), реальная аналитика трендов, чат в комнате.

## Критерии готовности

1. Старый «Челлендж 75» после обновления живёт в новой системе с тем же прогрессом; поля «якорь/остаток» из Настроек исчезли.
2. Из каталога стартуется новый челлендж, чекинится с вкладки и с «Сегодня», strict-провал и завершение работают; всё переживает синк и перезапуск.
3. «Бросить вызов другу» выдаёт ссылку; друг с айфона открывает её без установки, присоединяется и чекинится; оба видят прогресс друг друга.
4. Тесты `npm test` (корень и `server/`) зелёные.
5. Офлайн-чекин shared-челленджа не теряется — досылается при появлении сети.
